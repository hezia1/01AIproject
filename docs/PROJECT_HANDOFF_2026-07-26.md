## 已交付实现与历史扫描证据

下列实现由代码和此前交付记录支持，本轮未重新执行目标扫描或更新扫描资源。
- SCA Docker 增强已按职责拆分：Syft 生成一次 SBOM，Grype 只读取 SBOM 做漏洞匹配，Trivy 默认只做配置与密钥检查；Grype 健康失败时 Trivy 才启用漏洞回退。过期 Grype 数据库不再在每次扫描中重复导入，同批次的配置/密钥结果独立于组件 CVE 数量保存，密钥原值不落库。
- SCA“扫描引擎与漏洞情报源”已增加 Grype 数据库检测与人工更新入口：显示 schema、构建时间和按 720 小时策略计算的预计失效时间；只有用户点击更新时才联网，下载后会再次校验，并与扫描共用 `artifacts/sca-offline/grype-cache`。
- SCA 快速与深度扫描均采用在线 OSV 优先策略；首个查询失败后整批回退人工准备的本地 OSV 镜像，在线结果不会自动写入镜像。显式离线 CI 仍保证不联网。
- SAST 社区规则更新已与扫描解耦：用户在治理界面确认 Semgrep Rules License 后才能从官方仓库显式下载，平台固定解析后的提交 SHA 并只保存安全 YAML；扫描不联网，按项目语言/配置类型挂载匹配的本地目录，执行版本和选择结果随引擎状态保存。社区规则属于本机 `artifacts`，不提交到公开仓库。
- DAST 候选适配已容忍源码中的 `${PORT}` 等动态 URL 模板，单条非具体 URL 不再让候选接口整体失败。SANDBOX 项目专属 Docker 目标的测试身份引导同时支持常见 HTML 表单与 JSON 注册/登录 API；凭据仍只保存在 API 进程内存，已上线目标不会自动注册。
- DAST 自动策略生成已修复超长 Finding 标题触发数据库 500 的问题：名称在保留用途后缀后限制为 200 字符，失败会回滚并在按钮旁显示原因，重复点击不会重复创建。Semgrep CSRF 中间件缺失已从 XSS 误分类修正为 `csrf-isolated-session`，状态变更方法优先。
- 本地数据库中的扫描和动态证据是本机存量数据，不是仓库交付物或本轮扫描结果；读取存量 `completed` 也不能证明工具此刻可用或建立通用性能基准。

## 当前能力边界

### SAST

- 已有项目规则、有限语义分析、Git 基线和可选七角色 AI 复核。
- SAST AI 的 `security_skill` 仍只是单次复核草案，不会自动进入注册表。知识中枢已具备独立的声明式 Skill 注册、版本、人工发布和现有 Finding 复核执行；尚未实现草案转换审批、外部 Skill 包安装/签名、行业语料或自动改写规则的学习闭环。

### DAST

- 当前候选来自 SAST/AGENT，SCA 不进入队列。
- 源码动态映射主要覆盖 EJS 与 JavaScript/TypeScript 文件族。
- 红/绿裁决必须满足类型专属证据条件；证据不足保持黄色或未验证。

### SANDBOX

- 已有受控启动规划、Docker 隔离、固定探针、事件和证据摘要。
- Node.js 端口发现会跟随 `package.json` 声明/启动脚本及常见 JS/TS 入口；启动前可人工校正端口和健康路径，失败诊断会显示网关实际连接参数。
- 自动辅助服务只覆盖 PostgreSQL/Redis。
- 没有完整文件、网络、进程、环境变量、系统调用监控，也没有 AI 自主攻击。

### ASPM

- 已有单项目总览、证据图、攻击链、整改、复测和报告。
- 已有同租户已发布知识的跨项目匹配推荐；没有项目组、跨项目风险图谱/趋势、SLA、工单、授权配额、完整审计中心或生产合规报告。

### 平台

- 请求链路已有本地身份中间件、数据库会话和管理员写入保护；项目接口仍使用共享工作区，尚无完整项目成员/租户授权边界。部分知识操作人仍取请求字段，不能宣称所有审计已统一绑定当前会话。
- SCA API CI 示例缺少登录接入；门禁对失败/部分扫描状态的处理仍有待补齐，不能把门禁通过等同于扫描成功。
- Redis 当前不是核心队列；API/Web 没有生产部署编排。
- 真实密钥、客户源码、离线情报和运行证据不得提交 Git。
