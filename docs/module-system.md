# 六模块现状与关系

更新日期：2026-09-04。六模块可以按项目启用、配置和执行，结果统一写入 PostgreSQL，并在项目级 ASPM 视图中汇总。模块注册表和前端文案必须只描述下列当前能力。

Web 使用本地 `user` / `admin` 两角色认证。两类用户都能新增、切换项目，选择五个执行模块并使用 ASPM 和安全知识中枢；管理员额外拥有管理中心和规则写入能力。普通用户仍可人工更新 Grype 数据库以及下载、更新 Semgrep 社区规则，因为这些属于扫描运行资源维护，不等于规则编写权限。

管理中心采用模块分组与配置分类，每次只展示一个模块的配置区域。SAST 默认政策、质量门禁、抑制项，以及 SCA VEX 写入由管理员维护；Semgrep 引擎与社区规则开关保留给普通用户。通用模块接入/更新接口不允许普通用户写入任意配置，重新接入保留保存的规则与策略；SAST 即时扫描/排队请求不能借单次参数替换管理员规则来源。SCA 例外申请、审批与 VEX 操作人来自当前会话。DAST 的执行确认仍可由普通用户在既有目标/路径/探针限制内完成；本次未建设可编辑的全局 DAST/SANDBOX 安全策略或 Skill 注册表。

项目接入层已支持本地目录、受控 ZIP 和 HTTP(S) Git 浅克隆，并对全部支持的依赖清单、源码及 Agent/MCP 配置生成准备度检查。现场陌生项目默认使用有文件数、体积和软时限的快速模式；达到限制时结果标记为部分覆盖。

## SCA：供应链风险分析

**已实现**：npm、PyPI、Maven、Go、Bundler、Composer、Cargo、NuGet 常见清单/锁文件解析；直接与传递依赖；SBOM；许可证；本地规则、OSV/离线镜像、CVSS/EPSS/KEV 导入；VEX、例外、依赖图、扫描差异、JSON/SARIF 和质量门禁。

**有条件实现**：在线 OSV、Syft、Grype、Trivy 取决于网络、固定工具或离线镜像。缺失时保留本地解析结果并显示情报降级。

**快速模式**：最多解析 200 个依赖文件和 3000 个组件；网络可用时继续查询在线 OSV，网络失败时回退本地 OSV 镜像与规则。快速模式只约束基础扫描范围，不覆盖用户明确勾选的 Syft/Grype/Trivy。增强引擎实际执行状态和降级原因随扫描批次保存。

**OSV 路由**：普通扫描先用单次查询判断在线 OSV 是否可达；可达时使用最多 8 个并发查询。网络失败时整批回退人工导入的 `artifacts/sca-offline/osv-mirror.json`，避免每个组件重复等待网络超时；平台不会把在线查询结果自动写入镜像。显式设置 `SCA_OFFLINE_ONLY=true` 或 CI 使用 `--offline` 时不发起网络请求。

**增强引擎编排**：Syft 对待测目录生成一次 CycloneDX SBOM；Grype 直接读取该 SBOM，不再自行遍历目录生成资产；Trivy 默认关闭漏洞扫描，只负责配置错误和明文密钥。Grype 数据库或执行不可用时，Trivy 才启用离线漏洞扫描作为回退。Grype 健康时，SBOM 漏洞匹配与 Trivy 源码检查并行执行；`.git`、`node_modules`、`dist`、`build`、`coverage` 和 `vendor` 等目录从 Trivy 扫描范围排除。SCA 概览的引擎管理区可读取 Grype 数据库 schema、构建时间及按 720 小时上限计算的预计失效时间；过期或缺失时由用户显式触发联网更新，更新后再次校验。检测、更新和扫描共用 `artifacts/sca-offline/grype-cache`，日常扫描继续设置 `GRYPE_DB_AUTO_UPDATE=false`。Trivy 回退命中作为漏洞证据，未命中不作为完整 SBOM 的无漏洞证明。配置/密钥结果与组件 CVE 分开计数，且不保存疑似密钥的原始匹配文本。

**边界**：尚无经过标注语料验证的漏洞准确率与生态兼容率；SCA Finding 当前不自动进入 DAST。

## SAST：智能静态审计

**已实现**：内置本地规则、项目规则包、Semgrep YAML 导入、Semgrep 社区安全规则的人工更新与本地固定版本、按项目技术栈选择规则、有限数据流、Git 基线与历史密钥证据、规则治理、扫描差异、SARIF、修复草案，以及可选的七角色 AI 复核。

**有条件实现**：DeepSeek 复核需项目启用并提供密钥；Semgrep 需预置固定引擎。内置规则始终来自仓库，社区规则必须由用户阅读并接受 Semgrep Rules License 后点击更新；更新动作从官方仓库解析提交 SHA 并写入本机 `artifacts`，不会把规则加入 Git，扫描过程本身不会访问社区仓库或 Registry。每次 AI 运行可生成 `security_skill` 草案，知识关联以当前项目历史为主。

**快速模式**：最多扫描 1200 个源码文件和 60 MiB 内容，以 45 秒软时限执行本地规则，并禁用 Git 历史密钥和外部 AI；快速模式不覆盖项目已保存的 Semgrep 开关，启用时会真实尝试执行并记录成功或降级状态。限制命中会保存结果并标记有界覆盖。

**边界**：这不是编译器级全程序分析；知识中枢可以审核发布项目经验并跨项目推荐，但尚无可直接执行的企业定制 Skill 市场、行业历史漏洞语料或自动改写规则的学习闭环。

## AGENT：Agent 供应链安全

**已实现**：扫描 Markdown Frontmatter、JSON、YAML、TOML 和常见 Agent/MCP/插件配置；识别指令、Prompt、Skill、MCP、工具和插件资产；归一化权限、资源、信任和差异；提供 CLI、SARIF、HTML 与门禁。

**有条件实现**：受控 Agent 运行时探针要求一次性 Docker 目标和目标侧证据合同。

**边界**：不会连接真实生产 MCP、调用真实副作用工具或推断未上报的运行时行为；私有源和公开报告能力不等于完整市场治理平台。

## DAST：有界动态验证

**已实现**：将受支持且上下文完整的 SAST/AGENT Finding 转成策略；支持审批、Dry Run、同源/路径/身份/请求预算限制、固定 HTTP 与浏览器探针、差分验证、证据归档、红黄绿裁决和专项报告。

**候选与裁决口径**：源码中的 `${PORT}` 等动态 URL 模板不是具体目标，解析失败时只丢弃该 URL，不影响其他候选。候选队列统计可进入动态验证的当前 Finding；三色裁决仅统计已经完成且具有完整运行证据的任务，因此执行前可以显示候选大于 0、裁决为 0。

**策略生成一致性**：自动策略名称会在入库前规范空白并限制为 200 字符，超长 Semgrep/本地规则标题不会阻断生成。同 Finding 与同适配器映射重复请求返回同一活动策略；映射版本变更时才归档旧策略并生成新草案。数据库异常会回滚并返回可读错误。CSRF 全称匹配先于 XSS，项目级中间件缺失不要求伪造注入参数，且动态策略优先使用状态变更方法。

**有条件实现**：需要可达的已授权目标，或由 SANDBOX 成功启动的一次性目标。文件上传、时延、浏览器和 Agent 运行时等专项探针各有独立证据门槛。

**边界**：当前源码到动态目标映射主要覆盖 EJS 和 JavaScript/TypeScript 文件族；不生成任意 PoC，不保证每个静态 Finding 都可动态验证。

## SANDBOX：隔离运行与证据采集

**已实现**：从项目文件推断受限启动计划；校验镜像、命令、端口、健康检查和辅助服务；在 Docker 内部网络中启动目标；执行固定 HTTP、浏览器、文件上传、时延和 Agent 合同探针；归档 HAR、截图、控制台、时延、事件和证据摘要。项目专属 Docker 目标还可通过常见 HTML 表单或 JSON 注册/登录 API 准备两名普通一次性测试用户，秘密值只保存在 API 进程内存中。

**有条件实现**：需要 Docker Engine、白名单镜像和项目兼容的非 root/只读/受限网络运行方式。自动辅助服务目前只覆盖 PostgreSQL 与 Redis。

**边界**：不是完整的文件/网络/进程/环境变量/系统调用监控平台，不执行 AI 自主攻击，也不照搬项目 Compose 中的主机挂载、密钥和任意命令。自动身份只尝试常见字段与端点；非通用认证协议需要显式登录适配器或管理员密钥引用，已上线目标绝不自动创建账号。

## ASPM：项目级治理与交付

**已实现**：单项目总览、模块结果汇总、显式证据关系图、攻击链、Finding 状态、整改与复测、动态证据回链和项目安全报告；知识中枢支持项目候选提交、证据发布门槛、人工发布/退回、版本历史、回滚，以及同租户内基于规则和风险分类的跨项目推荐。

**边界**：知识推荐不等于跨项目风险图谱，也不会自动应用规则；尚无项目组、组织趋势、授权配额、完整审计中心、SLA/工单、生产级合规报告、独立 CVSS/EPSS 计算模型或租户权限执行。CLI/CI 门禁属于各扫描模块，不应表述成 ASPM 已交付的统一流水线平台。

## 模块依赖

```text
SCA ───────────────┐
SAST ──► DAST ──┐  │
AGENT ─► DAST ──┼──┼──► ASPM（单项目治理）
                 │  │
          SANDBOX ──┘
```

- SCA、SAST、AGENT 可独立执行静态扫描。
- DAST 当前从 SAST/AGENT 获取候选，不从 SCA 获取候选。
- SANDBOX 为需要隔离目标的 DAST/Agent 验证提供运行环境和证据。
- ASPM 聚合事实，不改变扫描器结论，也不在证据不足时自动提升裁决；知识中枢只推荐已审核知识，是否采纳仍由当前项目人员决定。
