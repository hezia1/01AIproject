## 实现

- 数据库迁移 `20260909_0018` 增加内置标记、SCA/SAST/AGENT 自动触发选择、运行触发来源和触发扫描任务 ID，并用唯一索引保证同一 Skill/扫描任务只自动执行一次。
- 5 个内置 Skill 是租户级资产，对该租户所有项目通用，不包含测试项目文件、路由、变量、行号或目录条件。
- 管理员可在“安全知识中枢 → 规则与 Skill”逐项选择自动触发模块；普通用户可查看触发方式，但不能修改。
- SCA、SAST（含本地 Worker 实际调用的扫描路径）和 AGENT 只在扫描状态成功提交为 `completed` 后调用 Skill。自动复核失败写入独立状态，不会把已经完成的专业扫描改写为失败。
- 项目删除会先清理该项目的 Skill 运行记录，再删除扫描任务；租户级 Skill 定义本身保留，避免自动运行历史通过外键阻塞项目清理。
- Skill 仍只复核当前 Finding，不重新启动、替换或改变专业扫描器，也不执行任意上传代码。

## 真实验证

- 首次迁移尝试失败：Alembic `op.execute()` 把确定性 UUID 字符串中的冒号解释为绑定参数。事务完整回滚，数据库仍为 `0017` 且没有种子数据；改用驱动层原生 SQL 后升级成功。
- 当前数据库和仓库迁移链头均为 `20260909_0018 (head)`，存在 5 个内置已发布 Skill 和 5 个 v1 版本。在确认数据库只有这 5 个内置 Skill、没有用户自建 Skill 和运行记录后，已实际执行 `0018 → 0017 → 0018`，降级和重新升级均成功；重新升级后仍为 5 个 Skill、5 个版本、0 条运行记录。
- 使用 `testproject` 最新已完成 SAST 扫描事件验证自动触发：3 个适用 Skill 首次生成 3 条完成记录；同一事件第二次执行生成 0 条，幂等成立。验收运行、对应审计以及临时写入的扫描元数据随后全部恢复/清理。
- 管理员将 SCA Skill 从 `sca` 自动触发改为仅手动，再恢复为 `sca` 成功；两条测试审计已清理。
- 当前 42 条有效 Finding 上的只读匹配：跨模块高危复核 22 条、SAST 有证据复核 23 条、SCA 高危复核 8 条、AGENT 权限边界复核 0 条、整改跟踪复核 0 条。这些是选择器命中，不是新增漏洞、召回率或扫描成功率。
