2. 完成差距项时，同时更新本表、`deferred-work.md`、受影响专题文档和机器可读验收清单。
3. 若 PPT 版本或哈希变化、模块边界变化、数据库迁移改变关键模型，必须重新核对受影响条目；不需要重新审计与变化无关的全部条目。

## 2. 当前结论

当前项目已经形成单机研发与演示范围内的六模块闭环原型：SCA、SAST、AGENT 可执行静态检查，DAST 和 SANDBOX 可进行有界验证与证据采集，ASPM 可做单项目治理，知识中枢已有声明式 Skill、版本、自动触发和单项目图谱。

与 PPT 的最终形态相比，主要差距集中在以下方面：

- “业务理解”目前主要是有界代码解析、单项目事实聚合和启发式关联，还不是经过基准验证的跨函数、跨语言业务语义分析。
- “自主进化”目前只有人工维护的声明式 Finding 复核 Skill、知识审核和推荐，没有知识到规则/Skill 候选的完整反馈闭环，也没有外部 Skill 包信任体系。
- “多智能体协同”目前是可选 DeepSeek 七角色顺序复核，不是可靠、可观测、可并发调度并经过效果评估的多 Agent 平台。
- “动态证明”已覆盖部分 SAST/AGENT Finding 和固定探针，但 SCA 不进入 DAST，映射范围、身份适配和重放基准仍有限。
- “沙箱行为监控”目前是 Docker 隔离、固定探针和声明式证据合同，不是完整文件、网络、进程、环境变量、系统调用监控或通用工具调用账本。
- “企业治理”目前以单项目为主，缺少生产级 IAM/租户隔离、项目组、跨项目风险图谱、组织趋势、SLA/工单、可靠任务、证据保护和生产部署运维。
- PPT 中的降本、提效、准确率提升、误报率下降、行业复制等预期没有版本化量化基准，当前不能声明已经实现。

## 5. 完成优先级

优先级按依赖和风险排列，不代表未排在前面的 PPT 能力不重要。

### P0：保证结论可信和平台不会越权

1. **真实失败状态与健康诊断（已完成当前范围）**：UI-010、基础健康和 DIAG-001 已区分情报时效、模型配置与最近调用证据、目标状态，以及 succeeded/partial/stale/failed/not-run 等任务语义；失败继续必须显示失败、降级或未知。
2. **CI 扫描状态语义（已完成当前范围）**：CI-002 与 CI-001 已完成；门禁只有完整、时效内扫描和政策同时通过才放行，认证/传输错误失败关闭。
3. **检测与动态验证基准（最小 v1 已收尾）**：QA-001 已完成小型语料；QA-002 已完成当前官方清单映射但跨项目扩展暂缓；DAST-001 已完成合同、成对目标和四类真实探针的当前范围，更大全策略矩阵暂缓。
4. **SANDBOX 安全基线（下一优先级）**：完成威胁模型和关键隔离负例，再扩大运行时行为采集或运行真实不可信项目。
5. **可信身份边界**：在进入多人或真实客户数据前，完成项目成员授权、统一租户过滤和服务端审计身份。

### P1：补齐 PPT 的核心差异化能力

1. **知识到能力的受控闭环**：知识候选转 Skill/规则候选，经过人工审核、固定语料评测、灰度和回滚后发布。
2. **行业/框架/业务型 Security Skill**：建立包格式、适用性、签名、依赖和安装治理，保持扫描器专业边界。
3. **业务语义与深层代码图谱**：扩展跨函数/跨文件/跨语言关系，建立误关联与漏关联基准。
4. **多智能体审计工程化**：增加可靠编排、角色合同、恢复、可观测性、模型版本与效果评估。
5. **静态到动态覆盖矩阵**：扩展 DAST 语言/框架/业务身份适配，并定义 SCA 可验证风险的安全边界。
6. **结构化运行时调用账本**：先统一 Agent 工具事件合同和完整性校验，再评估更深行为监控。

### P2：形成企业治理和可私有化交付

1. 生产 IAM、SSO、细粒度 RBAC、配额和完整审计中心。
2. 可靠任务系统、批量任务、服务账号、Webhook 和稳定开放 API。
3. API/Web 生产镜像、TLS、监控、升级/回滚、备份和恢复。
4. 证据对象存储、加密、签名、保留策略和合规报告。
5. 项目组、跨项目风险关联、组织趋势、SLA、工单和统一审批。
6. 行业漏洞知识库和企业误报经验运营体系。

### P3：规模化、生态扩展和体验优化

1. 完整生态兼容矩阵及更多语言、移动端、工作区和复杂工程支持。
2. 更多受控运行时、辅助服务和非 HTTP 场景适配。
3. 服务端游标分页、前端路由级分包、性能和完整 E2E。
4. 时区感知时间迁移及长期告警清理。
5. 在已有租户隔离和实体对齐基础上建设组织级代码/业务/风险图谱。
