SCA 与 SAST 治理前端也已改为任务型五工作区：SCA 使用“概览、风险组件、依赖影响、例外与 VEX、历史与报告”，SAST 使用“概览、代码风险、AI 辅助复核、扫描策略、例外与报告”。默认首屏不再平铺历史、规则、CI、Worker 和报告等管理能力；它们按用户任务进入对应工作区。Semgrep 明确归属 SAST，并作为补充本地规则覆盖面的增强引擎在扫描策略首项直接可见；社区安全规则由用户确认许可证后单独更新到本机固定版本，扫描按技术栈离线选取，不会隐式联网或随仓库分发。SCA 不展示 Semgrep。增强开关现已与真实执行一致：快速范围不会再覆盖 SCA Docker 或 Semgrep 配置，扫描历史会保存工具执行/降级证据；无 npm 锁文件时，SCA 可在临时隔离源码副本中生成依赖快照而不修改原项目。SCA Docker 流程由 Syft 单次生成 SBOM、Grype 读取 SBOM 匹配漏洞、Trivy 独立检查配置和密钥；仅当 Grype 不可用时才由 Trivy 回退匹配漏洞。SCA 引擎管理区可检测 Grype 数据库有效期，并在过期或缺失时显式更新同一份本地缓存，扫描过程不自动联网更新。

SANDBOX 启动规划已覆盖 `app.js`、`index.js`、`main.js`、`server.js` 及常见 `src/` JS/TS 入口，并会跟随 `package.json` 声明和启动脚本定位入口。页面在创建隔离实例前展示可校正的容器端口与健康检查路径；目标不可达时会明确显示网关使用的端口、健康路径和排查建议，错误端口不会被包装成成功运行。项目专属 Docker 目标支持通过常见 HTML 表单或 JSON API 准备内存态一次性测试身份；源码中的 `${PORT}` 等动态 URL 不再导致 DAST 候选接口整体失败。

DAST 自动策略生成已统一处理超长上游标题，在 200 字符数据库上限内保留策略用途后缀；保存异常会回滚事务并在生成按钮旁显示明确结果。对同一 Finding 重复点击是幂等的。Semgrep 的 `cross-site request forgery` 现会精确分类为 CSRF，项目级 CSRF 缺失在无显式注入参数时仍可生成隔离会话策略，并优先选择 POST/PUT/PATCH/DELETE。

状态词统一如下：

- **已实现**：代码、接口和持久化路径存在，并有自动化测试或本地运行证据。
- **有条件实现**：需要 Docker、固定镜像、第三方扫描器、离线情报或模型密钥；缺失时会明确降级或阻塞。
- **未实现**：不得作为现有能力宣传，包括生产级 IAM/租户权限执行、跨项目风险图谱与组织趋势、分布式任务、完整运行时系统观测和已量化的精确率/召回率。知识中枢当前只实现同租户已发布知识的规则/分类匹配推荐。
