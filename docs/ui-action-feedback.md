# 按钮与表单反馈

更新日期：2026-09-04。本次仅修改前端交互，不改变扫描算法、权限、规则或下载策略。

## 反馈规则

- 所有现有页面的按钮使用 `FeedbackButton`，表单使用 `FeedbackForm`；实际 DOM 仍为 button/form，保留原来的标签、布局、键盘交互和浏览器必填校验。
- 可用按钮点击后立即短暂高亮；导航/开关继续使用原有选中状态，不为每次切换弹出提示。
- 异步操作显示“处理中”及忙碌标记，等待期间禁用对应提交入口，并用同步锁阻止连续点击/回车重复提交。此锁只保护当前页面操作，不替代服务端幂等性，也不会终止已提交的任务。
- 普通 JSON 请求、报告下载和 ZIP 上传接入请求级失败反馈；即使原页面 catch 后只设置局部消息，捕获到的请求错误仍会显示全局红色提示。原局部反馈继续保留。
- 请求或异步回调结束后，统一提示“操作已结束，请查看页面结果”，不把 HTTP 200、排队成功、客户端超时或回调结束解释为扫描成功/下载成功。实际业务结果仍来自已有页面和服务端记录。
- 自动加载与后台轮询不产生点击提示；最新操作的提示优先，旧操作完成不会覆盖较新的提示。错误可手动关闭，完成提示自动收起；提示不遮挡底层正常操作。
- 禁用按钮保持不可操作，不制造虚假的点击/成功反馈。减少动画偏好下停止旋转动画，忙碌文字与键盘焦点仍可见。

## 维护方式

共用组件、样式及交互状态分别位于 `apps/web/src/action-feedback.tsx`、`action-feedback.css`、`action-feedback-state.ts`。API 包装仍保持原响应与错误语义。新增按钮/表单应复用组件，异步点击回调应返回 Promise，不使用 `() => void asyncOperation()` 丢弃返回值；并继续在业务区域展示准确的保存/扫描/验证结论。

`npm run test:feedback-ui` 检查现有 TSX 没有绕过共用组件的原生按钮/表单，并验证：处理中/中性完成/失败、快速双击、页面内部处理错误、下载错误与响应体保留、同步异常、回车提交、HTML 必填校验、后台请求隔离以及移动端提示边界。该测试使用模拟接口，不执行扫描或下载。
