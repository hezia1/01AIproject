# 暂缓事项与未完成能力清单

更新日期：2026-09-01。

本文档是项目暂缓事项的长期跟踪入口。下列内容经确认对生产化和能力证明有价值，但当前阶段以单机研发、受控演示和核心功能完善为主，因此暂不实施。

## 维护规则

1. 状态只使用：`暂缓`、`进行中`、`已完成`、`取消`。
2. 开始实施某项时，将状态改为“进行中”，并补充负责人、计划范围和开始日期。
3. 完成某项时，不删除原条目；必须改为“已完成”，填写完成日期、验收结果、证据路径和 Git 提交。
4. 部分完成不能标记“已完成”，应在进展记录中说明已交付和剩余范围。
5. 需求、边界或优先级发生变化时，同步更新本文档和 [`acceptance-baseline.md`](acceptance-baseline.md)。

## QA-001：检测效果基准语料

### 当前缺口

- 现有自动化测试主要验证代码行为，不代表真实精确率或召回率。
- 演示项目中的 Finding 数量不是经过标注的效果基准。
- SCA 更适合补充依赖解析覆盖率、情报完整率和已知漏洞匹配率；SAST/AGENT 才直接使用精确率、误报率和召回率。

### 预计交付物

- 固定版本的正例、负例和边界样本。
- 样本标签、来源、适用模块、期望规则与许可证说明。
- 可重复运行的指标计算脚本。
- 按模块和漏洞类型输出的 precision、recall、false-positive rate。
- 阈值、失败样例、差异报告和产物哈希。

## QA-002：外部项目官方漏洞逐项映射

本轮按用户要求暂不实施。当前已修复增强引擎执行语义、补充高价值 JavaScript/TypeScript 规则并归并重复位置，但不会宣称这些改动已经覆盖某个外部项目官方列出的全部漏洞。后续若启动该项，需要先固定测试项目提交和官方说明版本，再以“一个官方漏洞项对应哪些静态证据、哪些需要 DAST/业务身份、哪些超出规则边界”的方式验收。

### 目标与非目标

- “官方 30 项逐项映射”是把固定版本的外部测试项目作为一套验收样本，逐项确认平台是否发现、由哪个模块发现、保存了什么证据以及未发现的原因；它不是把规则写死到该项目的文件名、路由名、行号或变量名。
- 测试项目是考试卷，不是扫描器的运行范围。最终产物必须仍可用于新的 Node.js/Express 项目，并通过其他项目正例和安全负例验证通用性。
- 不以 Finding 数量等于官方条目数量作为唯一目标。同一漏洞的多处代码位置应归并并保留全部证据；同一问题被本地规则和 Semgrep 同时发现时应跨引擎去重。
- 不把所有条目都宣称为 SAST 漏洞。组件漏洞、安全配置缺口、Git/密钥风险、代码质量问题和运行态可利用性应分别统计。

### 模块职责

| 问题类型 | 主要负责模块 | 说明 |
| --- | --- | --- |
| SQL、命令执行、动态代码执行、JWT、Cookie、路径、敏感响应 | SAST | 使用通用 AST、语义数据流、本地规则和离线 Semgrep 规则，输出可复核代码位置 |
| 登录无限流、缺少 Helmet/输入验证/请求体限制、未关闭响应指纹 | 项目级 SAST 配置分析 | 需要分析路由、框架初始化和安全中间件是否缺失，不能只做逐行正则匹配 |
| IDOR、管理接口授权、跨 Controller/Service 数据流 | SAST 候选 + DAST/SANDBOX 复核 | SAST 给出静态候选和缺失控制证据；实际身份边界与可利用性需要运行态验证 |
| `.env` 被跟踪、密钥历史、忽略规则错误 | Git/SAST | 需要读取 Git 索引和历史，而不是仅判断磁盘上存在文件 |
| Express 等依赖版本及 CVE | SCA | 由锁文件/临时隔离依赖树、SBOM 和漏洞数据库负责，不在 SAST 中重复计数 |
| 未使用函数、安全 TODO、静默 catch、魔法数字、混合异步和日志级别 | 代码质量/安全卫生 | 与可利用漏洞分开展示，可作为治理提示但不抬高漏洞数量 |

### 通用实现原则

- 规则匹配语言和框架语义，例如“任意 Express 登录路由缺少限流”，不得只匹配 `/api/login`。
- 数据流跟踪通用 Source → Propagation → Sink → Sanitizer，例如任意请求输入跨函数进入 SQL 或命令执行，不得绑定固定变量名。
- 缺失性检查以项目结构、路由、中间件和配置事实为依据；无法证明缺失时标记“需要复核”，不得伪造确定漏洞。
- 框架适配可以分别实现 Express、Flask、Django、Spring 等规则，但规则必须属于框架，不属于某一个测试仓库。
- 离线 Semgrep 规则包必须固定版本和校验值，记录实际执行状态；“已启用”只代表配置生效，不代表自动具备完整规则覆盖。

### 预计交付物与验收

- 固定外部项目 commit、官方问题清单版本和许可证/来源记录。
- 逐项映射表：官方编号、问题类型、负责模块、通用规则 ID、预期证据、实际结果、置信度、未检原因和下一步验证。
- 分层统计：SAST 安全漏洞、安全配置缺口、Git/密钥风险、代码质量问题、SCA 组件漏洞、待 DAST/SANDBOX 验证问题，以及官方基准覆盖率。
- 至少一个不同来源的 Node.js/Express 正例项目，验证新增规则可迁移；不得与当前测试项目使用相同文件结构或变量命名。
- 安全负例和边界样本，验证参数化 SQL、固定命令参数、正确 JWT/Cookie/Helmet/限流/输入验证等实现不会产生明显误报。
- 自动化回归报告同时计算逐项召回、重复归并、误报和未覆盖原因；不得用原始行命中数替代独立问题数。
- 对 Python、Java 等其他生态单独建设和验收规则覆盖，不能用 Node.js/Express 基准代表全平台 SAST 能力。

## DAST-001：DAST 重放基准

### 当前缺口

- 已有动态验证和证据归档能够证明流程可执行，但不能证明跨版本、跨重复运行的裁决稳定性。
- 尚未形成固定的红色、黄色、绿色和未验证重放矩阵。

### 预计交付物

- 固定源码版本、目标镜像哈希、初始化数据和测试身份合同。
- 每类案例对应的策略、探针、预期证据和预期裁决。
- 重复运行次数、裁决一致率、证据完整率和失败原因统计。
- 修复前/修复后成对案例，以及超时、目标不可达、证据缺失等负例。

## IAM-001：生产级 IAM

### 当前缺口

- 数据库存在部分用户、租户和成员模型，但请求链路尚无可用的生产身份中间件。
- 当前大部分接口仍以受控开发环境和默认租户运行。
- 当前策略变更和例外操作中的本地操作者名称只是开发环境审计字段，不是经过认证的真实身份；界面也不应据此宣称具备角色权限或真实审批能力。

### 预计交付物

- 支持的认证方式、会话生命周期和退出/吊销机制。
- 管理员、安全工程师、研发和审计角色的权限矩阵。
- 根据真实身份和 RBAC 结果控制菜单、操作入口、只读状态和审批动作的角色驱动界面。
- 项目与租户数据隔离、DAST/SANDBOX 审批身份和完整审计记录。
- 未认证、越权、跨租户、会话固定和权限变更回归测试。
- 安全部署、密钥管理和应急恢复说明。

## SBX-001：完整 SANDBOX 安全评估

### 当前缺口

- 当前已有受限 Docker 目标、固定探针和代表性策略测试，但不是完整 EDR、系统调用监控或独立逃逸评估。
- 当前能力适合受控研发和演示，不能据此承诺安全运行任意不可信客户代码。

### 预计交付物

- 明确资产、攻击者、信任边界和逃逸路径的威胁模型。
- 网络、文件系统、进程、Linux capability、资源、密钥、挂载和容器生命周期负例。
- 镜像来源、签名、版本锁定和供应链验证。
- 独立安全评估报告、高风险问题整改记录和复测证据。
- 对生产执行环境、专用节点或更强隔离方案的最终决策。
