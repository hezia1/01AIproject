# AI 原生应用安全检测、验证与治理平台 PRD

版本：当前实现基线，2026-08-29。

## 1. 产品定位

平台面向已获授权的本地代码仓库和受控运行环境，将 SCA、SAST、Agent 供应链审计、DAST、SANDBOX 与 ASPM 串成一条项目级证据链。当前产品目标是可解释、可复现的研发与演示闭环，不是可直接公网部署的企业多租户 SaaS。

## 2. 当前用户与环境

- 安全工程师：配置项目、执行扫描、审批动态策略、复核证据和裁决。
- 研发人员：查看 Finding、修复建议、状态和复测差异。
- 项目负责人：查看单项目风险总览、攻击链和报告。
- 平台研发人员：维护规则、适配器、执行镜像和验收证据。

“平台管理员、组织管理员、审计员”等角色是未来目标。当前没有完整登录、RBAC 或租户隔离，不能以生产角色模型对外承诺。

## 3. 已实现产品范围

### 项目与资产

- 通过本地源码目录、受控 ZIP 上传或 HTTP(S) Git 浅克隆接入项目；ZIP 拒绝路径穿越、符号链接和超限内容，Git 禁止交互式明文凭据。
- 创建和更新项目，配置源码路径、仓库信息、运行地址和受限沙箱参数；应用管理的 ZIP/Git 源码在删除项目时一并清理，本地目录不会被删除。
- 探测全部已支持的依赖清单、源码、Agent 配置和常见启动上下文，并形成源码、SCA、SAST、AGENT、DAST、SANDBOX 的项目准备度检查。
- 按项目启用六模块并保存配置。
- 快速演示模式关闭 Git 历史密钥和外部 AI，并以依赖文件、组件、源码文件、体积和软时限约束基础扫描范围；SCA 在网络可用时查询在线 OSV，网络失败时回退人工导入的本地 OSV 镜像及本地规则。快速模式不会覆盖用户明确勾选的 SCA 容器增强或项目已启用的 Semgrep，增强引擎会真实执行并记录成功、降级或失败状态；达到上限时保存部分结果并明确标记。

### SCA

- 多生态依赖解析、组件快照、直接/传递关系、SBOM、许可证风险。
- 本地规则、OSV/离线镜像、CVSS/EPSS/KEV 导入、VEX、例外、差异和门禁。
- JSON/SARIF 输出与本地/平台 CI 接入。

### SAST

- 本地与项目规则、Semgrep YAML、有限数据流、Git 基线、历史密钥证据。
- Finding 证据、规则治理、扫描差异、SARIF、修复草案和可选 AI 复核。
- AI 只提供辅助结论；关闭、裁决和代码修改仍由人或确定性流程控制。

### AGENT

- Agent 指令、Prompt、Skill、MCP、工具和插件配置解析。
- 权限/资源边界归一化、信任评分、差异、SARIF/HTML 和质量门禁。
- 受控 Agent 运行时合同可提供动态证据，但不连接真实副作用工具。

### DAST 与 SANDBOX

- 从受支持的 SAST/AGENT Finding 生成有界策略，进行审批和 Dry Run。
- 对已授权同源目标执行固定 HTTP、浏览器、文件上传、时延和 Agent 合同探针。
- 在一次性 Docker 目标中进行隔离验证，归档事件、HAR、截图、控制台、时延和合同证据。
- 基于证据给出红色可利用、黄色不确定、绿色不可利用或未验证。

### ASPM

- 单项目组件/Finding/验证/证据汇总。
- 显式证据关系图、攻击链、Finding 状态、整改、复测和项目报告。

### 安全知识中枢

- 当前项目 Finding 可提交为持久化知识候选，并保留来源项目、Finding、规则、适用范围和证据引用。
- 只有具备 DAST/SANDBOX 证据或已完成修复/关闭/误报治理结论的候选可以由人工发布。
- 发布、退回和回滚形成不可覆盖的版本历史及审计事件。
- 已发布知识在同一租户内共享，并按相同规则或风险分类向其他项目推荐；推荐不会自动修改规则或 Finding。

## 4. 关键产品规则

1. 未执行、被策略阻止、目标不可达或证据不完整时，不得给出绿色。
2. 静态 Finding 不等于可利用漏洞；动态裁决不覆盖未进入候选队列的发现。
3. AI 输出不得直接改变证据事实、自动关闭 Finding 或执行真实攻击动作。
4. 自动识别项目失败时必须返回阻塞/降级原因，不得伪造扫描或启动成功。
5. 项目 Compose、README 或 Agent 指令属于不可信输入，不得绕过镜像、命令、网络、挂载和资源白名单。
6. 所有扫描和验证只允许用于明确授权的源码和目标。
7. 未满足证据门槛的知识候选不得发布；跨项目知识只能在同一租户内推荐，且不得自动改变扫描器或治理结论。
8. 快速扫描达到文件、体积或时间边界时只能标记为有界/部分覆盖，不得把“快速完成”解释为完整安全覆盖。

## 5. 有条件能力

- DeepSeek AI 复核需要项目开关、独立密钥和数据出境许可。
- 在线 OSV、Semgrep、Syft、Grype、Trivy 依赖网络或预置固定工具/镜像。
- Git 接入只接受 HTTP(S) 地址；私有仓库是否可用取决于主机已有 Git 凭据，前端和数据库不接收仓库密码或令牌。
- SANDBOX 与浏览器证据依赖 Docker Engine、固定镜像和项目兼容的受限启动方式。
- 红/绿 Agent 动态裁决依赖目标实现结构化运行时证据协议。

外部条件不满足时，产品必须保留本地事实并显示明确的降级、阻塞或黄色状态。

## 6. 未实现范围

- 生产级登录、SSO、RBAC、组织/租户隔离和不可抵赖审计。
- 项目组、跨项目关联、组织趋势、SLA、工单和统一审批中心。
- 完整业务/代码知识图谱、企业行业历史漏洞语料、可执行定制 Skill 市场和自动规则学习。
- 自动 PoC 生成、任意攻击脚本、完整运行时行为/系统调用监控。
- API/Web 生产部署包、HA、对象存储、证据独立加密和签名报告。
- 已经由标注语料证明的准确率、误报率、召回率和全生态兼容率。

## 7. 当前验收原则

- 功能验收以代码、数据库迁移、自动化测试、构建结果和可复现的受控运行证据为准。
- 后端测试必须使用 `D:` 盘临时目录，以满足 Agent 暂存安全边界。
- 前端至少通过生产构建；当前无自动化 UI 回归，因此只能视为部分验证。
- 准确率、召回率、DAST 复现率和生态兼容率在没有版本化语料前标记“未建立基线”，不得填入估算值。
- 生产可用性验收必须在 IAM、部署、备份、审计和证据保护完成后另行开展。
